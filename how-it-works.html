How Maplew works

Maplew (the file is called plew-map.html) plots the rows of a table as points on a picture. This page shows what happens to your files from the moment you drop them to the moment you share the result. The first half needs no coding knowledge. The second half is a map of the internals for people who maintain or extend the tool.

Part 1 · For everyone

Your data's journey, in six steps

Everything happens inside your browser. Your files are never uploaded anywhere; closing the tab discards them.

1 · Bring your files

Drop everything at once onto the drop zone or the main area: your table, a background picture if you have one, and any audio, video, images or transcripts the table mentions. No picture? Press No background for a blank plot frame.

You do

  • Drop a .csv, .tsv or .json table.
  • Optionally drop a map or figure image.
  • Optionally drop media files named in the table.

Maplew does

  • Sorts files by their ending (see the table below).
  • Reads the header row and decides what each column is for.
  • Treats an image as the background unless a table cell names it.

Good to know

  • Label columns with loc::, dim::, med::, desc:: for reliable results.
  • Write decimals with a point (46.5), not a comma.
  • A status line under the drop zone lists what was found and what is missing.

2 · Pick X and Y (Location columns)

Two columns decide where each row sits. Maplew guesses them for you and you can change the guess.

You do

  • Check the X and Y dropdowns.
  • Tick Web Mercator only if the background is a screenshot of a web map (Google Maps, OpenStreetMap).

Maplew does

  • Guesses in this order: loc:: columns, then names like lon/lat or x/y, then the first two numeric columns.
  • Counts rows whose coordinates are not numbers and tells you how many will be skipped.

Good to know

  • X and Y need not be geography. Any two numeric columns make a scatter plot.
  • After changing X or Y, press Reset to defaults in the next step so the edge values are guessed again for the new columns.

3 · Calibrate

Calibration tells Maplew which data value sits where on the picture. Without it, points still appear but are only stretched to fill the frame.

You do, one of

  • Image edges: type the data value at the left, right, top and bottom edge.
  • Three-point: click three places on the picture and type their coordinates. Handles tilted or scanned maps.
  • Pixels: nothing; the table already holds pixel positions.

Maplew does

  • Prefills the edges from your data's range so something shows at once.
  • Marks that prefill in yellow as approximate until you replace it.
  • Redraws on every change.

Good to know

  • With No background the prefill is all you need.
  • You may never need to type anything: a saved CSV, a sidecar file or a setup file can carry the calibration.
  • Loaded a different table and see no points? Press Reset to defaults.

4 · Style the points (Encodings)

Choose which columns drive colour, size and shape. The legend is built from those choices and doubles as a control panel.

You do

  • Pick a column for Color, Size and Shape, or leave any at "none".
  • For numeric columns choose continuous (a gradient) or categorical (one colour per value).
  • Adjust sliders and toggles under Display.

Maplew does

  • Proposes a first colour and shape column.
  • Builds filter chips for every categorical choice.
  • Mirrors the legend onto the map so it stays visible with the sidebar closed.

Good to know

  • Click a legend entry to hide or show that category.
  • Each legend row has its own colour, size or shape override.
  • Shape has 8 symbols and only suits categories.

5 · Explore and edit

Hover a point for a summary. Click it for the full record with its media. Scroll to zoom and drag to pan.

You do

  • Click: open the record.
  • Shift+click: edit it.
  • Alt+click a second point: compare side by side.
  • Ctrl/Cmd+click: mark it.
  • Under Edit positions: drag points or click the map to add one.

Maplew does

  • Plays audio and video, shows images, embeds YouTube links.
  • Shows ELAN and Praat transcripts in step with the audio.
  • Records every move, edit, add and delete so you can undo it.

Good to know

  • Zooming and panning never change your data.
  • Spread stacked points separates rows that share one location, on screen only.
  • Edits live in the browser until you save. Leaving the page asks first.

6 · Save and share

Three buttons, three different things. Most people want the first two together.

You do

  • Save to CSV: your table, with edits and calibration.
  • Export setup: the look of the plot, as a small JSON file.
  • Snapshot PNG: a picture of the plot for a paper or slide.

Maplew does

  • Adds one reserved row to the CSV holding the calibration.
  • Writes column roles into the CSV headers as prefixes.
  • Draws the snapshot at the background image's full resolution.

Good to know

  • The background image and media are never inside the CSV or setup file. Send them alongside.
  • Load a setup file with Import setup, not by dropping it on the drop zone.
  • See what each save keeps.

Two smaller saves: Change log (Edits section) downloads the list of edits you made, and Download ELAN / TextGrid (in a record) saves corrections typed into a transcript. Neither is included in the three above.

To hand a complete plot to someone else, send four things: the saved CSV, the setup JSON, the background image and the media files.

Where calibration comes from

Calibration can travel with your files in three ways. When more than one is present they are applied in this order, so the later one wins.

  1. Reserved CSV rowA row starting __PLEWMAP_CALIB__, written by Save to CSV. Read when the table loads.
  2. Sidecar fileimage.png.calib.txt next to a background. Sets the four edge values when that image is shown, and again each time you switch basemap.
  3. Setup JSONApplied last, by Import setup or automatically on an example page.
  4. PrefillEdges guessed from your data's range plus 6%. Shown in yellow as approximate.

Anything you type afterwards overrides all of them. Reset to defaults returns to the prefill.

Part 2 · For maintainers

Under the hood

One HTML file, one global state object S, one redraw function renderAll(). Almost every control follows the same loop.

The loop: a control fires its handler → the handler writes to S (or leaves a value in the DOM) → the handler calls renderAll() → the SVG overlay, both legends, the filter chips and the sidebar's visible sections are rebuilt from S.

Select any box for what it does and which functions to read. Function names match the source; the source is grouped under banner comments with the same headings.

Things that are easy to miss

  • Display settings are not in S. Point size, opacity, outline, ring, graticule, jitter, drag and add modes are read from their checkboxes and sliders during each redraw. displaySnapshot() collects them for the setup export.
  • Column facts are cached. classifyColumns() fills S.cols[h] = { role, numeric, uniq }. Anything that changes a cell or a role must call it again, which every edit path does.
  • Legend categories are more than the data. legendCategories(col) merges the column's unique values with any value that has a custom colour, size or shape, so an override survives when its last row is filtered or edited away.
  • Zoom is a CSS transform on #mapZoomWrap. The SVG's viewBox is always the image's pixel size, so point coordinates are image pixels at every zoom level.
  • Two transforms, both invertible. dataToPixel() draws; pixelToData() turns a drag or a click back into data values. Both pass Y through projY() / invProjY() when Mercator is on.
  • The Hugo site adds nothing to the app. Each layout reads plew-map.html and inserts one <script> after <body> that sets window.PLEW_HUGO, and on example pages window.PLEW_EXAMPLE (the manifest URL) and window.PLEW_SETUP. The last lines of the app's script act on those.
